## 2. Требования к аппаратному и программному обеспечению

**Аппаратные требования (минимально):**
- CPU: 4 ядра
- RAM: 8 ГБ
- Диск: 40 ГБ свободного пространства

**Программные требования:**
- Операционная система: Linux (рекомендуется **Astra Linux**; поддерживаются Debian/CentOS-совместимые дистрибутивы)
- **Docker** версии 24.0 и выше
- **Docker Compose** v2 (плагин `docker compose`)
- Доступ в сеть Интернет для загрузки образов контейнеров

---

## 3. Состав поставляемого экземпляра

Экземпляр ПО передаётся в виде архива `lemnity-<версия>.tar.gz`, содержащего:
- `docker-compose.prod.yml` — описание состава и параметров запуска контейнеров;
- `.env` — файл параметров окружения (заполнен значениями для проверки);
- каталог `clickhouse-config/` — конфигурация аналитической СУБД;
- образы контейнеров (`images/*.tar`) **либо** реквизиты доступа к реестру образов;
- настоящую инструкцию.

Состав сервисов: веб-сервер/обратный прокси (Nginx), сервер приложений (Node.js/NestJS),
коллектор событий, шлюз очередей (RabbitMQ), СУБД PostgreSQL, аналитическая СУБД ClickHouse,
объектное хранилище MinIO (S3-совместимое).

## 4. Порядок установки

### 4.1. Подготовка

1. Распаковать архив в рабочий каталог:
   ```bash
   tar -xzf lemnity-<версия>.tar.gz -C ~/lemnity && cd ~/lemnity
   ```
2. Убедиться, что установлены Docker и Docker Compose:
   ```bash
   docker --version
   docker compose version
   ```

### 4.2. Загрузка образов контейнеров

**Вариант А — образы поставлены в архиве:**
```bash
for img in images/*.tar; do docker load -i "$img"; done
```

**Вариант Б — образы загружаются из реестра** (требуется авторизация, реквизиты переданы отдельно):
```bash
echo "<TOKEN>" | docker login ghcr.io -u "<USER>" --password-stdin
docker compose -f docker-compose.prod.yml pull
```

### 4.3. Запуск инфраструктурных сервисов

```bash
docker compose -f docker-compose.prod.yml up -d postgres rabbitmq clickhouse
```
Дождаться состояния `healthy` всех трёх контейнеров:
```bash
docker compose -f docker-compose.prod.yml ps
```

### 4.4. Инициализация базы данных

```bash
docker compose -f docker-compose.prod.yml run --rm server \
  pnpm --filter @lemnity/database exec prisma db push --accept-data-loss
```

### 4.5. Запуск полного стека

```bash
docker compose -f docker-compose.prod.yml up -d --force-recreate --remove-orphans
docker compose -f docker-compose.prod.yml --profile setup run --rm minio_setup
```

### 4.6. Проверка состояния

```bash
docker compose -f docker-compose.prod.yml ps
```
Все сервисы должны находиться в состоянии `running` / `healthy`.

## 5. Доступ к экземпляру и проверка работоспособности

1. Открыть в браузере веб-интерфейс: `http://<адрес-сервера>/`
2. Войти с тестовой учётной записью:
   - Логин: `<demo-login>`
   - Пароль: `<demo-password>`
3. Демонстрация целевой функции (чат-виджет): открыть страницу
   `http://<адрес-сервера>/<страница-с-виджетом>` — в правом нижнем углу
   отображается чат-виджет; отправленное в нём сообщение поступает оператору
   в веб-интерфейс.

**Признак успешной установки:** веб-интерфейс доступен, выполняется вход,
чат-виджет отображается на странице и обеспечивает обмен сообщениями между
посетителем и оператором.
